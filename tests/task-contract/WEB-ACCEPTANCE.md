# W54 Web 完整验收执行单

依据原规格 §6 与已核验 WS-01–WS-05。此单是等待固定预览后的操作与取证脚本，**不是已经执行的浏览器结果**，也不替代现有 `e2e/task-contract.spec.ts` 的入口自动测试。实际表单尚不存在，不虚构其选择器或把 API 操作说成用户完成了表单。

## 启动前与统一取证

TARS/Data 的固定 SHA 隔离预览 manifest、loopback Web/API、专用 `multica_wush54_` 数据库、无真实智能体及停止说明齐备后，先运行 `node tests/task-contract/preflight.mjs`，再运行 `pnpm exec playwright test e2e/task-contract.spec.ts`。入口的登录、创建、评论、刷新任何一项失败，先记录环境/入口首败，不把后面的合同操作计为通过。

每例记录：源码 SHA、浏览器版本、合成工作区/任务/调用者 ID、合同版本、实际请求与状态码、界面截图、操作前后运行数量、handoff/admission/receipt ID。凭据与完整私人正文不进入证据。每例独立任务，用 TestApiClient 建立和清理数据；UUID、Source.revision、文件摘要来自实际 seed。基准内容沿用 `w54New` 的完整可写快照，不复制规格示意 ID。智能体场景只绑定测试创建的假可执行文件。

## 操作与预期

| WEB-02 | FR/A-01/06 → FD-01/06 → SP-01/06 → TC-02/03/16 | 打开合同编辑，分别删除目标、验收、禁止、停止条件、接收人；每次尝试发布 | 对应字段提示；不采用合同、不增版本、不派工；空数组和缺失/null 区分；补全后草稿保留。 |
| WEB-03 | FR/A-01/06 → FD-01/06 → SP-01/06 → TC-01/16 | 在真实表单填入完整最小合法快照并发布，刷新 | 当前 v1 展示完整目标、边界、验收、停止条件及责任人；GET 与提交一致；只读字段由服务端产生；无运行增量。 |
| WEB-04 | FR/A-03/06 → FD-03/06 → SP-03/06 → TC-01/10/16 | 显式交给当前合成成员，确认目标/动作；接收成员本人确认 | 提交前不是 accepted；pending 与 accepted 可区分；receipt 绑定版本、本人、摘要和动作；无 agent task。其他成员不能代确认。 |

## 与当前自动测试的边界

API/运行时矩阵已在 `task_contract_*_test.go` 中执行或停于真实缺入口；本单把可见交互与后端事实逐项对应。固定预览到位后，MOSS 按实际控件语义补自动选择器并执行上述操作；当前没有浏览器通过结论。产品内部 WS-05 接点仍需实现方提供，不用浏览器网络拦截冒充真实数据库事务故障。
